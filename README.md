# Vocal Journal

Vocal Journal — приватное русскоязычное рабочее пространство для вокальных упражнений, песен, записей занятий и совместной работы с преподавателем.

Сейчас реализованы основа приложения, управление упражнениями и тегами, а также библиотека песен. Для песни можно хранить метаданные, статус, ссылку на YouTube, форматированный текст и общие комментарии к выбранным фрагментам текста.

## Технологии и архитектура

- React, TypeScript в строгом режиме, Vite и Tailwind CSS
- React Router
- Cloudflare Worker с типизированным REST API
- Cloudflare D1 (SQLite) и миграции Wrangler
- Zod для серверной валидации
- Tiptap/ProseMirror для структурированного текста песен
- Vitest, Testing Library и Miniflare
- ESLint

Vite проксирует запросы `/api` на локальный Worker по адресу `http://127.0.0.1:8787`. Локальная D1 хранится в `.wrangler/` и сохраняется между перезапусками. Облачные учётные данные для разработки не нужны.

Планируемая production-архитектура: фронтенд в Cloudflare Pages, API в Cloudflare Workers, D1 для данных, Cloudflare Access для входа и Backblaze B2 для медиафайлов.

## Локальный запуск

Требуется Node.js 22 или новее и npm.

```bash
npm install
npm run db:migrate:local
npm run dev
```

`npm run dev` одновременно запускает Vite и Wrangler. По умолчанию интерфейс доступен на `http://localhost:5173`, а API — на `http://localhost:8787`.

При необходимости процессы можно запустить раздельно:

```bash
npm run dev:api
npm run dev:web
```

## D1 и миграции

Исходные SQL-миграции находятся в `migrations/`:

`0001_exercises_and_tags.sql` создаёт:

- `exercises` — упражнения, заметки, зарезервированные ссылки на плюс и минус;
- `tags` — теги с отдельным нормализованным именем для уникальности без учёта регистра;
- `exercise_tags` — связь многие-ко-многим с составным первичным ключом и каскадными внешними ключами.

`0002_songs_and_lyrics_comments.sql` создаёт:

- `songs` — метаданные песни, один из трёх статусов, безопасную YouTube-ссылку, структурированный документ текста и зарезервированный `minus_media_id`;
- `lyrics_comments` — общие комментарии к тексту с внешним ключом на песню;
- индексы для хронологической выдачи песен и комментариев.

Применить неприменённые локальные миграции:

```bash
npm run db:migrate:local
```

Показать состояние локальных миграций:

```bash
npm run db:migrations:list
```

Локальная база и служебные файлы Wrangler исключены из Git. Перед облачным развёртыванием нужно создать production D1 и заменить локальный `database_id` в `wrangler.jsonc`; это не требуется для локальной разработки.

## API

Все успешные JSON-ответы имеют форму `{ "data": ... }`, ошибки — `{ "error": { "code", "message", "fieldErrors?" } }`.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/api/exercises` | Список упражнений с тегами |
| `POST` | `/api/exercises` | Создать упражнение |
| `GET` | `/api/exercises/:id` | Получить упражнение |
| `PUT` | `/api/exercises/:id` | Изменить название, комментарий и теги |
| `GET` | `/api/tags` | Список тегов с количеством упражнений |
| `POST` | `/api/tags` | Создать тег |
| `PUT` | `/api/tags/:id` | Переименовать тег |
| `DELETE` | `/api/tags/:id` | Удалить тег и его связи |
| `GET` | `/api/songs` | Список песен от старых к новым |
| `POST` | `/api/songs` | Создать песню |
| `GET` | `/api/songs/:id` | Получить песню, текст и комментарии |
| `PUT` | `/api/songs/:id` | Изменить метаданные, статус или YouTube-ссылку |
| `PUT` | `/api/songs/:id/lyrics` | Сохранить структурированный текст |
| `POST` | `/api/songs/:id/comments` | Создать комментарий и его аннотацию атомарно |
| `PUT` | `/api/songs/:id/comments/:commentId` | Изменить текст комментария |

Запросы валидируются на сервере, идентификаторы имеют формат UUID, SQL-параметры передаются через `bind`, а связанные изменения выполняются атомарным D1 batch. YouTube-адрес нормализуется на сервере; в iframe попадает только URL, построенный приложением для проверенного 11-символьного video ID.

## Песни и аннотации текста

Песни выводятся по дате создания от старых к новым с ID как вторичным ключом. Поддерживаются статусы «Изучаю», «Выучена» и «Отложена». На странице песни можно менять статус, смотреть YouTube-плюс, редактировать текст и работать с комментариями. На широком экране активный комментарий находится сбоку от текста; на мобильном он открывается в компактной нижней панели.

Текст хранится не как HTML, а как проверяемый ProseMirror JSON. Разрешены только абзацы, переносы строк, полужирное и курсивное начертание, четыре цвета выделения и внутренние метки аннотаций. Поэтому произвольный HTML не сохраняется и не рендерится.

Каждый комментарий получает UUID, который записывается непосредственно как `annotation`-метка на выбранном фрагменте документа. Правки в других местах не сдвигают такую привязку, как это произошло бы с сырыми символьными offset-ами. Сохранение нового комментария и обновлённого документа выполняется одним D1 batch. Если пользователь удаляет отмеченный текст, комментарий сохраняется и возвращается как осиротевший (`isOrphaned: true`), а не переносится на другой фрагмент. Перекрывающиеся аннотации намеренно не создаются: один выбранный фрагмент может иметь один комментарий.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `VITE_API_BASE_URL` | Нет | `/api` | Базовый URL Worker API для браузера |

Для локальной разработки достаточно значения из `.env.example`. Переменные с префиксом `VITE_` видны браузеру, поэтому в них нельзя хранить секреты Cloudflare или Backblaze B2.

## Структура проекта

```text
migrations/       # SQL-миграции D1
worker/           # Worker API, валидация и интеграционные тесты
src/
  api/            # типизированный клиент и запросы
  app/            # маршруты и оболочка
  components/     # навигация и переиспользуемый UI
  domain/         # доменные модели
  features/       # формы и логика упражнений, песен и редактора текста
  hooks/          # загрузка данных и защита несохранённых изменений
  pages/          # страницы маршрутов
```

## Текущее состояние и ограничения

- Упражнения создаются, редактируются, сортируются по русскому алфавиту, ищутся по названию и фильтруются по всем выбранным тегам.
- Теги создаются, переименовываются и удаляются без удаления связанных упражнений.
- Удаление упражнений, корзина и восстановление ещё не реализованы.
- Песни создаются и редактируются; текст поддерживает ограниченное безопасное форматирование и несколько комментариев.
- Перекрывающиеся аннотации текста не поддерживаются. Удалённая аннотация остаётся в списке как осиротевший комментарий; автоматического повторного прикрепления нет.
- Аутентификация Cloudflare Access пока отсутствует. Решение об авторизации удаления тега изолировано в Worker, но endpoint сейчас не защищён.
- Удаление песен и комментариев не реализовано.
- Загрузка и хранение медиа, минусовки, аудиоплееры и попытки записи не реализованы.

Следующая задача не должна менять эти ограничения без отдельной спецификации.
